## After Stage 2 (Tasks 1-2, commits 3565bb3 and a46c3de)

Measured on 2026-11-12, game build 58.15.3: 791 card rows = 511 released, 31 upcoming, 249 token/other; 230 locations; meta period 137 with 4,763 lists in 2,810 clusters, 345,061 games, baseline win rate 57.7%, 48 archetypes (1,323 lists unlabelled), 11,134 stored pairs; 598 images on disk (22 rows have no art on the host: 3 tokens and 19 upcoming).

- **Card rows.** The `cards` table and `tests/fixtures/cards.json` hold raw Untapped rows; class is computed at load from `now`. `toCard(row, now, fixes?)`. The fixture's default `now` is its `capturedAt`. Helper exports: `fixtureDb(now?)`, `fixtureRows()`, `fixtureColliders()`, `textFixes()`, `deckNames()`, `deckText()`, `resetFixtureDb()`.
- **Class trap.** A `collectible` row with `series: 0` (ElderDragonOfTheMoon) becomes `token`, not `released`, once its date passes unless cards are re-synced. For "upcoming, then legal" tests use a recently released card with an earlier `now`.
- **Text shape.** `Header: body` with straight quotes. Objective cards read `Objective: goal -> reward. (0/N)`. Flavour-only text is `''`. Upcoming rows can have junk placeholder text. 25 rows get their dropped numbers from `sync-data/card-text-fixes.json`.
- **Names.** `byName` uses a letters-and-digits key (`normalizeName`). No two released cards collide; 24 non-released rows collide with a released name. Display names can differ a lot from defIds ("Doctor Doom 2099" is `Doom2099`).
- **Meta.** `MetaList.cards` is sorted by defId and `key` is that joined with `|`; lists are ordered by games descending. `MetaArchetype.sample` is the most-played list, `topCards` up to 16 from the manifest, `planId` null until the features step sets it. `winDelta` is null under 200 games. Pair counts and clusters are written by the meta step.
- **Reference decks** (`tests/fixtures/decks/`: fantomex, kluh, magneto, zombie, arthur, patriot) use the site block: `# (cost) Name` lines, `#`, a short code, `#`, a comment. The short code was produced by a small encoder in `src/ingest/fixtures.ts`; Task 3 must cross-check it against its port of `docs/research/analysis/deckcode/deckcode.mjs`.
- **Features hook.** `fixtureHooks.compute` in `tests/helpers/fixture-db.ts` is null, so `features()` is undefined and `edges()` empty. Task 5 sets it and calls `resetFixtureDb()`. `src/ingest/features.ts` is a stub.
- **Sync.** Images download serially, 1 s apart. `pnpm sync meta` refuses within 6 h of the last run unless `--force`.

## After Task 3 (rules and import/export)

72 tests in `tests/engine/{rules,io}.test.ts`; suite 142 tests.

- **Exports beyond the plan.** `rules/formats.ts`: `RANKED`, `findFormat(db, id)`, `isCheckedFormat(fmt)` (verified and constructed), `formatName(db, id)`. `io/deckcode.ts`: `shortCardCode(defId)`, `DECK_CODE_TOKEN`. `io/resolve.ts`: `tidy`, `candidates`, `lookup`, `resolveLine`, `rejectReason`, `LIST_LINE` (shared line reading; use these for any name search).
- **Unverified modes.** `validateDeck` gives `MODE_UNVERIFIED` (warning) and checks Ranked rules only; `isLegal` can still be true. The UI must call `isCheckedFormat(findFormat(db, deck.format))` before claiming a pass for the mode itself. Draft gives only `MODE_NOT_CONSTRUCTED` (info). An unknown format id is treated as unverified.
- **Extra codes.** `SKILL_CARDS` (info, one line naming the skills; no cap known). `gateFor` also returns `IN_DECK`; gate order: UNKNOWN_CARD, NOT_DECKABLE, UNRELEASED, IN_DECK, MODE_BANNED, NOT_OWNED. `NOT_DECKABLE.cardIds` holds the token plus the released cards whose `tokens` create it.
- **Not implemented:** checks 10 `STATS_STALE`, 11 `RECENTLY_CHANGED`, 13 `ROTATION_SOON`: the CardDb has no sync date or balance-change log. `UNKNOWN_CARD` says "since the card sync" without a date for the same reason.
- **Decoding.** `decodeDeckCode` keeps unknown ids as written (an unknown short piece stays a short code), accepts any card count, padding-less and URL-safe base64, and returns null for anything else (a short code needs at least one known piece). `parseDecklist`: the first code anywhere in the text wins (also embedded in a sentence) and other lines are then ignored; tokens never resolve, upcoming cards do (validation reports them); `parseCollection` owns released cards only. Collection unresolved entries are strings, decklist ones carry line numbers.
- **Export.** `exportDecklist` sorts by cost then `localeCompare(name, 'en')` and writes the short code in that order; it reproduces the six fixture blocks byte for byte. No code unless 12 different known cards; unknown ids are written `# (?) id` so re-import reports them.
- **Cross-check.** The six fixture short codes agree with the port and with `deckcode.mjs` itself (`decode` + `encodeShort`, byte-equal).

## After Task 4 (card-text parser)

Measured 2026-11-13 on the fixture pool (511 released, 504 with text).

- **API.** `parseCard(card) -> { clauses, unparsed }` (`src/engine/text/parse.ts`, also re-exports `TRIGGERS`, `EFFECT_KINDS`, `TARGETS`); `classifyPhrase(text)` maps a noun phrase to a target. `loadOverrides(json)` + `applyOverrides(card, parsed, overrides) -> { clauses, unparsed, staleOverride }` (`overrides.ts`; the JSON is `{ about, cards: { defId: { reviewedText, note, clauses } } }`). `coverage(cards, parsedById)` and `attributeMismatches(card, clauses)` (`coverage.ts`). Task 5 should feed features from `applyOverrides(card, parseCard(card), loadOverrides(json))`.
- **Clause shape.** One clause per sentence (two for "On Reveal and When Destroyed"); clauses can have zero effects (set-up sentences). Text without a header has trigger `static`, or a sentence trigger from `PASSIVE` (`on_own_play`, `static_cost`, `play_restriction`, `moveable`, ...). Objective: trigger `objective`, the requirement is a condition `obj:*`, the reward is the effects. `effect.selectors` holds `sel:*` tags of that effect's phrase, including `sel:other` ("your other cards"). Magnitudes are unsigned for `afflict` and `cost_reduce`.
- **Target conventions** are written at the top of `tests/fixtures/clause-audit.json` and in `vocab.ts`: `self`, `own_here`/`enemy_here`/`all_here`, `*_anywhere` (named locations count as anywhere), `own_other_locations`, `own_hand`/`own_deck`/`enemy_hand`/`enemy_deck`, `both` (both players, hands or decks), `own`/`enemy` (a side, no zone), `*_player`, trigger subjects (`own_next_played`, `own_played_card`, `enemy_played_card`, `own_moved_card`, `enemy_moved_card`, `own_drawn_card`), `location`. Negative Power on any card is `afflict`; `copy_card` targets where the copy lands; `resurrect` whose card returns.
- **Numbers.** Clause audit: 123 hand-read cards, parser alone 123/123 trigger+kind+target. The audit was also the development set, so this overstates held-out accuracy: a review of the other 381 cards' output found about 25 target errors, fixed in the parser, and the ones still known are listed below (about 2% of cards). Fully read sentences: 494/504 cards by the parser alone (prototype 93.5%), 504/504 with the 16 overrides. Attribute cross-check: 8 disagreements (Cannonball, Khonshu, Ozymandias, Spider-Ham tokens; Kingpin, Techno-Organic Virus, Web Sling magnitudes).
- **Known gaps.** Namora reads `own_anywhere` (the condition "alone at another location" hides the location); Storm Horseman buffs only `own_hand` (misses "here"); Web Sling's "+1 Power when it moves" is folded into `grant_moveable`; Prodigy copies `all_anywhere` (should be the card in front, `own_here`); Sersi gets a spurious `cost_increase`; Nightmare and Spider-Ham get two `copy_text` effects; Terrax's "losing player's deck" is read `enemy_deck`; Debrii and Shanna "add to each location" are read as your side (text does not say, mechanics §6 q6). Of the 46 cards of mechanics §5 only 16 have overrides (those the parser cannot read plus Doctor Octopus FF, found wrong in review); the rest rely on the parser.

## After Task 5 (features and network)

Measured 2026-11-13 on the fixture pool and the real database (same 511 released cards): 542 cards with features (released + upcoming), 14,457 edges, 1,049 strong, 1,767 net negative; `pnpm sync features` takes 0.6 s. Coverage on that run: 0 cards without a clause, 0 unparsed sentences, 8 attribute disagreements, no stale override. Suite 287 tests.

- **API.** `computeFeatures(card, overrides, poolStats, metaStat)`, `computeNetwork({ cards, meta, overrides }) -> { features, edges }` (features for released + upcoming, edges between released only), `modelOf(clauses)` (`features/compute.ts`). `traitsOf`, plus clause queries `effs`, `tagsOf`, `hasTag`, `hasTrigger`, `costPred`, `powerPred`, `isDrawback`, `restrictionOf` (`features/traits.ts`). `AXES` (each also has `weight`, `enablerRule`, `payoffRule`, `enabler(view)`, `payoff(view)`), `AXIS_BY_ID`, `axesOf`, `view(card, clauses)` (`features/axes.ts`). `TECH_ROLES`, `techRolesOf` (`features/tech.ts`). `poolStatsOf(cards)`, `qualityOf`, `textValue`, `measuredPoints` (`features/quality.ts`). `buildEdges(cards, featuresById)`, `ruleFirings`, `STRONG = 0.5` (`network/edges.ts`). Ingest: `syncFeatures(db, log, { now, root })` returns a summary, `readOverrides(root)`, `strongest(edges, n)`.
- **Fixture hook is on.** `fixtureDb()` computes features and edges at test time with `fixtureOverrides()` (exported from `tests/helpers/fixture-db.ts`). Set `fixtureHooks.compute = null` and call `resetFixtureDb()` for a bare database.
- **Axes.** `CardFeatures.axes[id] = { e, p, heuristic }`, `e`/`p` are 1 (text reading), 0.5 (cost or Power guess) or 0. 32 axes; `heuristic` on the axis means one side can be a guess. Deck-level checks that are not pairs (payoff with no enabler in the deck, play restriction unreachable) are not computed here: Tasks 6-7 use `axes` and `restriction` for them.
- **Tech roles** (`TechRole` ids): ongoing-removal, text-removal, on-reveal-denial, power-reset, cost-lock, add-lock, reduction-immunity, big-card-removal, sweeper, destroy-lock, hand-attack, deck-attack, created-tax, displacement, lockdown, protection. `deck-attack` and `created-tax` go beyond the spec §8.2 list (theory §3 rows).
- **Edges.** One per unordered pair, `a < b` by defId; direction lives in the reasons (`label` says who enables whom; `detail` quotes both texts as `Name: "sentence"`, or `Name (cost/power, no ability)`). Reason `value` is the fan-out weighted strength `strength / log2(2 + max(fanA, fanB))` (prototype used the geometric mean; changed after the audit, see below). Pair synergy = (best family + 0.5 x other families) / 1.2, capped at 1; anti the same; `score = synergy - anti`. A family counts once per pair (`one_cost` with `filter:cost`, `big_power` with `filter:power`, `discard` with `discard:selector_hit`, `destroy` with `mass:destroy_feeds`). Heuristic reasons (axes bounce, cost_reduction, energy_ramp, sequencing, multi_play, location_control, go_wide, alone, or any side read from cost or Power) cap synergy at 0.49. `sameLocation` follows the best synergy reason (else any anti) being location-scoped.
- **Edge audit.** `tests/fixtures/edge-audit.json`, seed 20261118, 60 strong edges hand-judged: **53 true, 4 lenient, 3 false: strict 88.3%, lenient 95.0%** (prototype 70% strict). Four earlier rounds (seeds 20261113-20261117: 50%, 72%, 77%, 92%, 88%) were used to fix rules and are not counted. The three false patterns (Luke Cage as a self-affliction payoff, printed negative Power counted as affliction, board effects picking skills) were fixed after this sample: strong set -18 / +4, the 4 new ones read and true; that final set has not been re-sampled. Tests: sampled true/lenient edges stay strong, false ones are not; 15 known-true strong; 15 unrelated not strong; 5 anti examples.
- **Quality** is heuristic: `50 + 4 x (Power - pool mean for cost - 2 if drawback) + 4 x text power-equivalents (capped -6..10, halved when conditional, doubled when scaled) + measured`, measured = `winDelta x 100 x games / (games + 50 x lists)`, clamped to +/-10. Pool means reproduce theory §1.5 (2.15 ... 8.59, 500 characters). Not calibrated against meta win rates.
- **Known gaps.** Strong edges favour precision over recall: broad true relations stay below 0.5 (Zabu x a 4-Cost card 0.39-0.495, Wong x an On Reveal card about 0.21, Mockingbird x a card creator 0.405). Remaining lenient patterns: conditional enablers (Namorita "if this is your only card here"), deck buffs x deck summoners (Agent Venom x Malekith), Phoenix Force merging into a revived card. Parser gaps of Task 4 flow through (Terrax reads `enemy_deck`, Debrii/Shanna as own side). `anti:filler_vs_space` from the prototype was dropped (weakest rule in its hand-check). `MetaArchetype.planId` is still null: tagging archetypes with plan families needs Task 6's `sync-data/plans.json`. The coverage report is printed and stored in `sync_state('features').info`; no UI yet.
